# 独立运行包 0.3.3：启动等待与模型目录缓存

2026-10-27。npm 启动器保持 0.3.0，官方 Codex 保持 0.163.0；本次运行包包含 native 0.4.3，内部平台包元数据为 0.1.4，不重新发布 npm 平台包。

普通启动和 login 移除独立 HTTPS 冷探测；需要完整网络观测时运行 doctor/ping。原生程序在鉴权 WSS 就绪后提供目录 scope，普通启动只有在已验证连接与本地目录 scope 匹配时才使用最多 60 秒的缓存并后台刷新。无缓存、超龄、未知已保存模型、旧服务端或旧 native 仍等待真实目录请求。

网关 0.4.3 按账户共享单个目录刷新，新鲜期默认 60 秒，过期后最多额外 300 秒可返回旧目录并后台刷新。缓存锁不等待上游网络；认证失效与刷新竞态有保护。目录是发现信息，不保证实时推理权限；推理请求不会自动重放。

部署新网关后，客户端运行：

```sh
mcodex update
mcodex runtime status
mcodex doctor
```

预期为 `Launcher 0.3.0; runtime 0.3.3; source: managed`，native 0.4.3、官方 Codex 0.163.0。更新不替换正在运行的旧会话，退出后重新启动 mcodex 使用新版。npm 启动器无需升级。

本地实现验证：162 项 Node 测试、语法检查；网关 112 项默认测试、实际 Codex 0.163.0 兼容验收、fmt 和严格 clippy 通过。覆盖阻塞目录、认证拒绝、旧版本回退、空目录、并发退出登录与凭据轮换。真实网络重传并未由此消除，启动耗时改善需要在用户机房更新后测量。
