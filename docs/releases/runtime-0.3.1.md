# 独立运行包 0.3.1：非登录 shell 目录修复

2026-10-27。npm 启动器保持 0.3.0，官方 Codex 保持 0.163.0，原生包保持 0.1.3 / 二进制 0.4.2。

在实际官方 Codex 0.163.0 中复现：会话 `<cwd>` 正确，`allow_login_shell=false`，但 Bash 的 `BASH_ENV` 或 Zsh 的 `.zshenv` 执行 `cd "$HOME"` 后，工具进入 HOME，相对文件读取失败。旧 10 项验收只覆盖条件性的登录脚本，没有包含这一非登录启动路径。新增回归在修复前失败。

现在工具 shell 先执行原有初始化，随后恢复本次执行器的入口目录。导出变量、函数、`--cd`、模型显式 workdir 与用户登录 shell 的显式 opt-in 保留。临时启动文件为 `0700` / `0600`，Codex 退出、错误、取消后清理；不移动 HOME/CODEX_HOME，不修改原始配置文件。用户显式目录选择或命令本身的 cd 仍由 Codex/命令处理。

0.3.0 用户通过以下命令安装独立运行包修复，再重新启动会话：

```sh
mcodex update
mcodex runtime status
```

无需发布或重新安装 npm 主包。此前已发布的 0.3.0 归档保持冻结。尚未取得报错机器的具体错误行与诊断，本文复现证明上述机制，不视为排除了其他路径错误。

本机 137 项 Node 测试、语法检查及工作流 actionlint 通过。官方 Codex 0.163.0 的 15 项真实工具目录验收通过，包括修复前失败的非登录初始化、变量/函数保留、显式目录、模型 workdir 与登录 shell opt-in。测试使用隔离 HOME/CODEX_HOME 和 loopback 合成响应，不调用生产网关或模型；固定命令的测试沙箱设置不作为生产 OS 沙箱验收。

运行包验收现从解压后的运行包导入其实际 `runCodex`，再执行全部工作目录用例，验证将要交付的业务代码与引擎。Linux CI 要求安装 Zsh，避免新回归被静默跳过。
