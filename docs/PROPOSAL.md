# mcodex：npm 安装的 Codex 网关客户端

## 目标

把目前需要独立二进制、配置文件和服务管理的客户端收敛成三个操作：`npm install -g @m9rco/mcodex`、`mcodex login`、`mcodex`。远端继续运行既有 MLab Gateway，保存订阅 OAuth，接受经 Token 认证的 WSS 长连接。

主包与开发仓库公开。mcodex 的连接地址由首次登录填写，配置模板使用示例域名。连接 Token 和 OAuth 凭据不进入 GitHub 或 npm 包。

## 架构选择

保留官方 Codex CLI 的交互界面、工具、沙箱、审批和会话能力，只在启动时注入自定义提供商参数。包装器不实现新的代理工具协议，也不把本机工作区交给远端执行。

Node.js 负责参数、首次设置、健康检查和生命周期；Rust 负责 HTTP/SSE 与 WSS 的数据通路。启动时用 `127.0.0.1:0` 绑定临时端口，生成只在本次进程有效的本机 API Key。Codex 通过 `MCODEX_LOCAL_KEY` 读取该临时密钥，Rust 则从受保护的文件读取远端连接 Token。

一个 Codex 进程对应一个转发进程。Rust 内部保持 WSS 连接并复用并发流。正常结束、信号或转发进程异常时，包装器负责停止子进程并清理自己的临时状态。

## 配置与分发

- 主包 `@m9rco/mcodex@0.1.1` 固定使用 `@openai/codex@0.162.1`，原生包版本维持 `0.1.0`。
- 三个平台包通过 npm `optionalDependencies` 分发预编译二进制，分别声明 `os` 和 `cpu`。
- 平台包只包含二进制、许可证、来源说明和校验值；安装时无需 Cargo、SSH、systemd 或额外下载脚本。
- 首次登录保存 `server` 和模型选择等非机密设置；连接 Token 单独保存，目录 `0700`、文件 `0600`。
- 每次运行通过官方 `-c` 参数设置模型提供商，不修改已有的 Codex 配置文件或主目录环境变量。

公开文档使用 `gateway.example`。网关 Token 不写进进程参数，也不传给 Codex 及其工具子进程。连接故障的诊断输出不应包含密钥。

## 兼容性

Linux x64、Linux ARM64、macOS ARM64 为首版范围。Linux 沿用通过 SHA-256 验证的 MLab Gateway `v0.3.2` 发布资产；macOS 使用同协议的 `v0.3.3` ARM64 构建。远端网关需支持对应协议与 Responses 接口。

真实 Codex 请求必须在远端支持的模型上完成 Responses 流式生成和本机工具调用验证。不能仅凭 `/v1/models` 返回成功判断可用，也不能通过删除有语义的请求字段来掩盖协议不兼容。

包装器保留用户传入的模型、工作目录、沙箱和审批参数。保留 `login`、`logout`、`doctor` 等包装器命令，其余调用传给官方 CLI。

## 性能判断

该方案减少配置和维护工作。热路径仍为原来的 Rust 程序，不新增 Node.js 逐块中转。npm 包装器的主要成本发生在启动和连接阶段。

不能据此承诺模型生成速度提高。延迟主要由客户端到网关的网络、网关到上游的网络及模型排队和生成决定。实际测试应说明机器与路径，避免把 Docker 模拟架构结果当作吞吐基准。

## 验收

1. 主包和三个平台包均能 `npm pack`，包清单无运行时配置和凭据。
2. 自动测试覆盖配置权限、输入验证、登录验证、参数透传、随机端口启动和退出清理。
3. 在干净 Linux Docker 环境从 npm 安装，无额外客户端安装和手工 TOML。
4. 用连接 Token 验证 WSS，执行真实官方 Codex 最小生成和读取本机测试文件的任务。
5. 验证失败、信号退出后无遗留转发进程；远端 OAuth 始终保留在网关。

CI 只使用测试夹具，不存生产连接 Token。真实网关测试属于发布验收，不能把生产凭据放入公共 Actions。

## 后续

首版完成后再考虑 Windows、macOS x64、版本升级提示和网关协议协商。官方 Codex 更新应先跑兼容性测试，再更新固定版本。此阶段不重写官方 CLI，不增加远端工作区执行，也不改变订阅账户与地区规则。
